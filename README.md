# LES-NET — клиентская часть

Статус: **0.1.0-dev — ручной WireGuard-прототип**, не готовое Windows/Android-приложение. Будущие клиенты, RouterOS и OpenWrt будут использовать **основной домашний LES-NET Server**, работающий в Ubuntu VM внутри Proxmox.

## Схема подключения

- Ubuntu VM: **главный VPN-сервер** `10.77.0.1/24`, будущий LES-NET Controller.
- У домашнего подключения есть выделенный публичный IP; **внешний VPS/relay не используется**.
- Если публичный IPv4 находится на WAN домашнего роутера, перенаправьте UDP 51820 на постоянный LAN-IP Ubuntu VM. Если публичный IPv4 непосредственно на VM — перенаправление не требуется.
- Windows: `10.77.0.10/32`, Android: `10.77.0.11/32`; каждому устройству нужна собственная уникальная пара WireGuard-ключей.
- [Серверные инструкции](https://github.com/DeadSoulf/LES-NET_server).

## Первый тест

1. Подготовить Ubuntu VM и входящий UDP 51820 по серверным инструкциям.
2. Установить официальный WireGuard для Windows/Android и сгенерировать **новую пару ключей на каждом устройстве**.
3. Добавить только публичный ключ клиента в `[Peer]` домашнего сервера с индивидуальным `AllowedIPs = 10.77.0.x/32`.
4. Локально заполнить соответствующий шаблон из `configs/`, указав публичный IPv4 или DNS **домашнего** сервера и публичный ключ сервера. Не публиковать заполненную конфигурацию с приватным ключом.
5. Активировать туннель с внешней сети, проверить handshake на Ubuntu VM и доступ к `10.77.0.1`.

Split tunnel: `AllowedIPs = 10.77.0.0/24`. Для маршрутизации LAN `192.168.1.0/24` нужны отдельные шаги серверной инструкции. Для full IPv4 tunnel у клиента `AllowedIPs = 0.0.0.0/0`, но только после настройки forwarding/NAT **на домашней Ubuntu VM**, с отдельной защитой IPv6 и DNS.

## План

LES-NET Controller, авторизация/управление сетями/ACL, собственное приложение Windows, Android, RouterOS 7/OpenWrt и затем P2P; на данном этапе автоматической регистрации устройств и виртуального Ethernet (L2) нет.
