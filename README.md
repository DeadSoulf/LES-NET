# LES-NET — клиентская часть

Собственная защищённая IP-сеть: Windows, Android, впоследствии MikroTik RouterOS и OpenWrt.

> Статус: **0.1.0-dev (сетевой прототип)**. Собственные графические клиенты пока не реализованы. Для первого испытания используются официальные WireGuard-клиенты и конфигурации из `configs/`. Не называйте эту заготовку готовым аналогом ZeroTier.

## Репозитории

- Здесь: клиенты, документация и примеры клиентских конфигураций.
- Сервер: [LES-NET_server](https://github.com/DeadSoulf/LES-NET_server) — Ubuntu VM в Proxmox и отдельный публичный WireGuard relay.

## Подключение

1. Развернуть публичный relay и подключить домашнюю Ubuntu VM по инструкциям серверного репозитория. VM находится за CGNAT и **сама инициирует** туннель; Proxmox-хост не служит VPN-шлюзом.
2. На Windows/Android установить официальный WireGuard-клиент и создать в нём уникальную пару ключей.
3. Передать администратору relay **только публичный** ключ устройства; администратор привязывает его к отдельному IP-адресу в конфигурации relay.
4. Заполнить локально шаблон из `configs/`, никогда не коммитить действующую конфигурацию с приватным ключом.
5. Проверить доступ к `10.77.0.1` (relay) и `10.77.0.2` (Ubuntu VM) после установления handshake. Для проверки доступности Ubuntu можно использовать SSH, если он установлен и разрешён.

Адреса в тестовой сети: relay `10.77.0.1/24`, Ubuntu VM `10.77.0.2/32`, Windows `10.77.0.10/32`, Android `10.77.0.11/32`. Проверяйте отсутствие конфликтов с существующими сетями.

## Режимы

- **Только LES-NET:** `AllowedIPs = 10.77.0.0/24`.
- **Весь IPv4 через relay:** `AllowedIPs = 0.0.0.0/0`; нужен IPv4 forwarding, NAT и разрешённая пересылка на relay. IPv6 и DNS требуют отдельной настройки во избежание утечек.
- **Домашняя LAN:** добавьте её подсеть в клиентский `AllowedIPs` и маршруты на relay/Ubuntu VM и обратный маршрут либо согласованный NAT на домашней стороне. Не используйте один и тот же LAN-префикс в разных местах.

## План

Сначала воспроизводимо проверяем прототип Windows ↔ relay ↔ Ubuntu ↔ Android. Затем создаём LES-NET Controller (авторизация, сети, ACL, выдача конфигураций без сбора приватных ключей), приложение Windows, Android, интеграции RouterOS/OpenWrt и в отдельной версии — P2P/NAT traversal. В версии 0.1 весь трафик проходит через публичный relay, это не ZeroTier L2 или полноценный mesh.
